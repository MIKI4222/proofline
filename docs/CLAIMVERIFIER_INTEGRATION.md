# ClaimVerifier integration — development preview

This frontend uses the ClaimVerifier contract at `0xAD841aD6C876dA20ecC380A71ADe8313B81d3C92` on Studio Dev (chain 61997), separately from MilestoneJudge. Public reads use the SDK and validate observed return structures. Owner-only writes reuse Proofline's wallet and transaction tracker. Claim registration requires instructions of 20–1000 characters; despite the product brief calling these optional, they are mandatory in the deployed code. The contract permits minimum source count 1, while maximum must be 2–5.

A read-only recheck on 2026-11-21 returned `get_claim_count = 0` for the current deployment; its deployed code matched the checked-in `contract/claim_verifier.py` after line-ending normalization. State can change or be reset. Earlier RPC and detailed claim reads on 2026-11-15 were against the previous deployment `0xa44D5A557a2B146e6aC5B8c674cA31d540d98175`; those results are historical and do not demonstrate records on the current address. No write transaction was sent and wallet signing, fee estimation, decision/finality and recovery for these claim operations have not been verified end to end. Contract state may change or be reset.

After a successful registration, locate the claim in Claims Explorer. The contract write returns no claim ID and the UI deliberately does not guess it from a global counter. Sources are append-only and verification is limited to the claim owner; the contract is authoritative.
